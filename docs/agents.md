# Workflow, tools and skills

LangGraph is the primary runtime. Its typed `ConversationState` moves from intent and skill selection to an LLM supervisor agent. The agent receives the conversation history, relevant skill instructions and an intent-scoped tool catalog. It can request a tool call; LangGraph executes only registered local tools, appends their result, and returns control to the LLM for the user-facing response. The loop is bounded to two tool rounds. Task and reminder reads are read-only; writes are limited to the authenticated user and run in the chat database transaction. Reminder tools require a timezone-aware schedule, and the prompt instructs the model to ask when timing is ambiguous. The LLM, rather than application code, interprets the user's request and makes recommendations.

Skills are a code-owned allowlist with descriptions, applicability keywords and instructions. Selection is deterministic; user/document text cannot register code or expand permissions. The current six skills are budgeting, career, education, purchasing, travel and time management. The `analysis.compare_allocations` tool adds up categories supplied by the LLM and checks them against an available total; it does not choose a winner or write advice. Browser Use is optional per message: the UI must grant browser access for the exchange and configuration must be enabled. It uses a local browser session to open GitHub search and repository pages and read visible page text before the chat model writes the answer. Page content is untrusted.

Configured Tavily research is available through both the separate research API and the chat tool loop. Browser Use is a distinct, explicit per-message opt-in. The catalogue reports configured capability state but does not claim a provider health check. No external NeMo Agent Toolkit integration or harness comparison is implemented. LangGraph state checkpointing and interrupted run resume remain unfinished.
# Tool and capability discovery

`app/tools/registry.py` is the authoritative registry for model-callable tools. `app/tools/catalog.py` registers built-ins; `registry.discover()` returns deterministic, OpenAI-compatible function definitions. Each definition also exposes sanitized UI metadata through `public_description()`.

Chat uses `select_relevant_tools()` to choose a bounded set from the current request, then filters Google tools by the authenticated owner's persisted connection scopes before exposing schemas to the model. Tool arguments are validated against the registered nested JSON-schema subset and execution is refused unless the tool was authorized for that model request. Google provider operations perform their own owner, connection, and scope checks again. The LLM never registers code or receives shell access.

The tool loop is bounded to two model tool-call rounds. Tool and provider results are treated as untrusted data. Research can be combined with an email or planning request when the actual request also calls for current external evidence. See [plugin-audit.md](plugin-audit.md) for the current integration inventory, test coverage and remaining limitations.
