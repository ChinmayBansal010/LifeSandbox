# Providers

`ChatModel` normalizes chat completions and function calls. `LLM_PROVIDER=mock` is the offline default and returns an echo-style demo answer; it does not reason over user prompts. For actual responses, explicitly select `LLM_PROVIDER=nebius` or `LLM_PROVIDER=openrouter` in `.env`, configure that provider's API key and model, then restart the API. Both use their OpenAI-compatible chat-completions HTTP APIs; requests use a bounded timeout and token limit. OpenRouter reasoning requests are retried once with reasoning disabled if no user-facing content is returned. If `OPENROUTER_FALLBACK_MODEL` is set, that model is tried next after an empty primary completion; it uses the same OpenRouter account and is recorded in the conversation state for subsequent tool turns. Live provider contracts have not been credential-tested.

`RESEARCH_PROVIDER=tavily` enables Tavily search and normalizes title, URL, limited excerpt, publisher and retrieval time. Disabled or failed research returns an explicit 503. `local_hash` embeddings are deterministic test utilities only. Neon Object Storage implements short-lived presigned PUT URLs over its S3-compatible endpoint. Provision a private bucket on the Neon branch and pull `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, and `AWS_ENDPOINT_URL_S3` from Neon; set `NEON_STORAGE_BUCKET` to the bucket name. The credential needs storage read/write scopes for the branch. The live Neon service has not been credential-tested. Redis, QStash, LangSmith and Langfuse runtime hooks are not active.

Browser Use provides an optional local Chromium browser for public GitHub research. Install it with `uv sync --locked --extra browser`, then install Chromium with `uv run browser-use install`. Set `BROWSER_USE_ENABLED=true` and select a configured `nebius` or `openrouter` model for the final answer. The chat UI requires a per-message opt-in. The browser navigates directly to GitHub search and repository pages, is restricted to `github.com`, and does not accept downloads or use an authenticated profile. The app reads visible page text and passes it to the configured chat model to write the answer. The project allows PyPDF 6 to satisfy Browser Use's dependency while retaining support for the app's current PDF processing.
