## Registry and discovery findings

- `app/tools/registry.py` is the authoritative function-tool registry. Built-ins register through `app/tools/catalog.py`; the LLM gets OpenAI-compatible function schemas.
- Before this change, registry entries lacked a common UI-safe metadata view and nested schema validation was shallow. Definitions now carry provider/category/version, sensitivity, output-contract and URL metadata fields, and the registry emits a sanitized public description. Input validation checks nested objects, arrays, bounds, enums and unknown properties.
- `GET /api/v1/plugins` now returns enabled registry definitions with an owner-specific Google connection status. It distinguishes code availability/configuration from connection scope; it does not claim external health.
- `GET /api/v1/plugins/executions` returns only authenticated-owner tool execution summaries, without private inputs or outputs.
- The chat selector is deterministic and bounded. It selects from natural-language intent families, then removes Google tools without granted scopes. `execute_tools` still validates arguments and checks that a requested tool was in the request's authorized set. Google API operations independently re-check owner, connection state and scopes.
- Tool execution is still implemented as a dispatcher branch in `app/conversation/graph.py`; provider adapters are not yet unified behind a separate interface. Async provider and follow-through calls use the registered timeout and are cancelled on expiry; local synchronous calculations are input-bounded. Safe automatic retries are not currently used.
- Current API has no separate capability health-check operation, generic OAuth lifecycle, or plugin enable/disable management. Google is the only account connection lifecycle. Unsupported calendar writes remain unavailable.

## Verification coverage gaps

Existing tests cover registry uniqueness/schema rejection, Google OAuth and operation behavior with mocks, approval snapshot checks, research, browser failures, memory, files, life management, and admin routes. The repository does not include a frontend test script or frontend test suite. No actual Google, Tavily, Mem0, Neon or Browser Use credentials were available for live provider verification. See `docs/integration-verification.md` for the prior manual verification record.
